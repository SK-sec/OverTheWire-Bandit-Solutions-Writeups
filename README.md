# 📚 Прохождение уровней

### 🔹 Level 0 ➔ Level 1
* **Цель:** Подключиться к серверу по SSH под пользователем `bandit0`.
* **Теория:** `ssh` (Secure Shell) используется для безопасного удаленного управления системой. Флаг `-p` задает порт, если он отличается от стандартного (22).
* **Команда:**
  ```bash
  ssh bandit0@bandit.labs.overthewire.org -p 2220
  # Пароль: bandit0
  ```
  
---

### 🔹 Level 1 ➔ Level 2
* **Цель:** Прочитать файл с именем `-` (дефис) в домашней директории.
* **Теория:** Знак `-` воспринимается многими командами как указание читать данные из стандартного ввода (stdin). Чтобы прочитать файл с таким именем, нужно явно указать путь (относительный `./` или абсолютный).
* **Команда:**
  ```bash
  cat ./-
  ```

---  
  
### 🔹 Level 2 ➔ Level 3
* **Цель:** Прочитать файл, имя которого содержит пробелы: `spaces in this filename`.
* **Теория:** В Linux пробел разделяет аргументы команд. Чтобы терминал воспринял всю строку как одно имя файла, её нужно обернуть в кавычки или экранировать пробелы обратным слэшем `\`.
* **Команда:**
  ```bash
  cat "spaces in this filename"
  # Альтернатива: cat spaces\ in\ this\ filename
  ```

### 🔹 Level 3 ➔ Level 4
* **Цель:** Найти и прочитать скрытый файл в папке `inhere`.
* **Теория:** Файлы, имена которых начинаются с точки `.`, скрыты в Linux. Обычная команда `ls` их игнорирует. Для их отображения нужен флаг `-a` (all).
* **Команда:**
  ```bash
  cd inhere
  ls -a
  cat .hidden
  ```

### 🔹 Level 4 ➔ Level 5
* **Цель:** Найти единственный текстовый файл (human-readable) в директории `inhere` среди бинарных файлов.
* **Теория:** Утилита `file` проверяет содержимое файла и определяет его истинный тип, не полагаясь на расширение. Ищем файл с типом `ASCII text`.
* **Команда:**
  ```bash
  cd inhere
  file ./*
  # Находим нужный файл (например, ./-file07)
  cat ./-file07
  ```

### 🔹 Level 5 ➔ Level 6
* **Цель:** Найти файл в `inhere` по критериям: размер 1033 байта, удобочитаемый, неисполняемый.
* **Теория:** Команда `find` осуществляет гибкий поиск. Аргумент `-size` задает размер (`c` — байты), `-readable` — права на чтение, а `!` перед ключом означает инверсию (отрицание).
* **Команда:**
  ```bash
  find inhere/ -type f -size 1033c ! -executable
  # Читаем найденный файл:
  cat [ПУТЬ_К_НАЙДЕННОМУ_ФАЙЛУ]
  ```

### 🔹 Level 6 ➔ Level 7
* **Цель:** Найти файл на всем сервере, принадлежащий пользователю `bandit7`, группе `bandit6` и имеющий размер 33 байта.
* **Теория:** Поиск от корня `/` генерирует много ошибок "Permission denied". Конструкция `2>/dev/null` перенаправляет поток ошибок (stderr) в виртуальное «пустое устройство», очищая вывод терминала.
* **Команда:**
  ```bash
  find / -user bandit7 -group bandit6 -size 33c 2>/dev/null
  # Читаем полученный путь:
  cat [ПУТЬ_К_ФАЙЛУ]
  ```

### 🔹 Level 8 ➔ Level 9
* **Цель:** Найти в файле `data.txt` единственную строчку, которая не повторяется.
* **Теория:** Утилита `uniq -u` выводит только уникальные строки, но она работает корректно только с предварительно отсортированным текстом. Используем конвейер `|` для передачи вывода `sort` в `uniq`.
* **Команда:**
  ```bash
  sort data.txt | uniq -u
  ```

### 🔹 Level 9 ➔ Level 10
* **Цель:** Найти пароль в бинарном файле `data.txt` после нескольких знаков `=`.
* **Теория:** Команда `strings` извлекает последовательности печатных (текстовых) символов из нечитаемых бинарных файлов. Результат фильтруем через `grep`.
* **Команда:**
  ```bash
  strings data.txt | grep "=="
  ```

### 🔹 Level 10 ➔ Level 11
* **Цель:** Декодировать пароль из файла `data.txt`, который зашифрован в формате Base64.
* **Теория:** Base64 — это схема кодирования двоичных данных в текст (ASCII). Для обратного декодирования в Linux используется встроенная утилита `base64` с флагом `-d` (decode).
* **Команда:**
  ```bash
  base64 -d data.txt
  ```

### 🔹 Level 11 ➔ Level 12
* **Цель:** Расшифровать файл `data.txt`, где все буквы латинского алфавита смещены на 13 позиций (шифр ROT13).
* **Теория:** ROT13 — частный случай шифра Цезаря. Команда `tr` (translate) заменяет одни символы на другие попарно. Мы указываем два диапазона (оригинальный алфавит и со смещением на 13 символов) для больших и маленьких букв.
* **Команда:**
  ```bash
  cat data.txt | tr 'A-Za-z' 'N-ZA-Mn-za-m'
  ```

### 🔹 Level 12 ➔ Level 13
* **Цель:** Извлечь пароль из файла `data.txt`, который представляет собой многократно сжатый дамп (hex dump).
* **Теория:** Этот уровень тренирует работу с архиваторами (`gzip`, `bzip2`, `tar`) и утилитой `xxd` (создание и восстановление hex-дампов). Процесс требует циклического переименования и распаковки файла в зависимости от его текущего типа, который мы проверяем через `file`.
* **Команды (примерный пошаговый процесс):**
  ```bash
  mkdir /tmp/my_workspace && cp data.txt /tmp/my_workspace && cd /tmp/my_workspace
  xxd -r data.txt data_bin          # Восстанавливаем из hex-дампа
  file data_bin                     # Проверяем тип (допустим, gzip)
  mv data_bin data_bin.gz && gunzip data_bin.gz
  file data_bin                     # Проверяем тип (допустим, bzip2)
  bzip2 -d data_bin                 # Повторяем до тех пор, пока file не покажет ASCII text
  cat data_bin
  ```

### 🔹 Level 15 ➔ Level 16
* **Цель:** Отправить текущий пароль на порт `30001` локального хоста с использованием SSL/TLS шифрования.
* **Теория:** Обычный Netcat (`nc`) не умеет работать с зашифрованными SSL/TLS соединениями. Для этого используется `openssl s_client`. Флаг `-connect` задает хост и порт, а `-ign_eof` предотвращает закрытие соединения сразу после отправки данных.
* **Команда:**
  ```bash
  cat /etc/bandit_pass/bandit15 | openssl s_client -connect localhost:30001 -ign_eof
  ```

### 🔹 Level 16 ➔ Level 17

* **Теория:** Сканирование портов. Можно использовать `nmap` с флагами `-p` (диапазон портов) и `-sV` (определение службы/версии). Найдя нужный порт, отправляем туда пароль через `openssl s_client`. Полученный в ответ текст (RSA Private Key) нужно сохранить в файл.
* **Команды:**
  ```bash

  echo "[PASSWORD_FROM_LEVEL_15]" | openssl s_client -connect localhost:31790 -quiet
  # Копируем вывод (от -----BEGIN RSA PRIVATE KEY----- до -----END RSA PRIVATE KEY-----)
  ```

* **Теория:** Программа `suconnect` подключается к указанному порту на `localhost`, ждет оттуда пароль от Level 20, сравнивает его и в случае успеха возвращает пароль к Level 21. Нам нужно запустить прослушивание порта в фоновом режиме (используя `&`) с помощью `nc`, а затем вызвать бинарник.

### 🔹 Level 22 ➔ Level 23
* **Цель:** Вычислить имя захешированного временного файла, в который `cron`-скрипт пишет пароль для `bandit23`.
* **Теория:** Скрипт в этом уровне делает то же самое, но имя выходного файла генерируется динамически на основе MD5-хеша от имени пользователя (`bandit23`). Мы можем вручную воспроизвести эту логику в терминале, чтобы узнать имя файла.
* **Команда:**
  ```bash
  cat /usr/bin/cronjob_bandit23.sh
  # Смотрим логику генерации имени. Воспроизводим её для пользователя bandit23:
  echo "I am user bandit23" | md5sum | cut -d ' ' -f 1
  # Получаем строку-хеш (например, 8ca78be6...) и читаем этот файл из /tmp:
  cat /tmp/8ca78be6...
  ```

### 🔹 Level 23 ➔ Level 24
* **Цель:** Написать собственный Bash-скрипт, который будет автоматически выполнен `cron`-задачей от имени пользователя `bandit24`.
* **Теория:** `cron` каждые пару минут выполняет все скрипты, находящиеся в папке `/var/spool/bandit24/foo/`, и затем удаляет их. Мы создадим простой скрипт, который скопирует пароль из защищенной директории `/etc/bandit_pass/bandit24` в доступную нам папку `/tmp`. Важно дать скрипту полные права на исполнение (`chmod 777`).
* **Команда:**
  ```bash
  mkdir /tmp/my_dir && cd /tmp/my_dir
  echo '#!/bin/bash' > script.sh
  echo 'cat /etc/bandit_pass/bandit24 > /tmp/my_dir/pass.txt' >> script.sh
  chmod 777 script.sh
  cp script.sh /var/spool/bandit24/foo/
  # Ждем около 1-2 минут, пока отработает cron:
  cat pass.txt
  ```

### 🔹 Level 24 ➔ Level 25
* **Цель:** Осуществить брутфорс 4-значного PIN-кода на порту `30002` вместе с текущим паролем.


### 🔹 Level 31 ➔ Level 32
* **Цель:** Запушить (загрузить) правильный файл в удаленный git-репозиторий, чтобы сервер в ответ прислал пароль.
* **Теория:** Базовый рабочий процесс в Git. Нам нужно создать файл, добавить его в индекс отслеживания (`git add`), зафиксировать изменения (`git commit`) и отправить на сервер (`git push`). Иногда файлы конфигурации `.gitignore` могут блокировать добавление. В таком случае используется флаг `-f` (force).
* **Команда:**
  ```bash
  git clone ssh://bandit31-git@localhost:2220/home/bandit31-git/repo
  cd repo
  echo "May I please have the next password?" > key.txt
  git add -f key.txt   # Игнорируем правила .gitignore, если они мешают
  git commit -m "Add key file"
  git push origin master
  ```

### 🔹 Level 32 ➔ Level 33
* **Цель:** Сбежать из ограниченной командной оболочки (`UPPERCASE shell`), которая превращает все вводимые команды в заглавные буквы и выдает ошибку.
* **Теория:** Escape from Restricted Shell. Оболочка переводит буквы в верхний регистр, из-за чего стандартные команды (вроде `ls` или `sh`) превращаются в `LS` и `SH` и ломаются. Однако позиционные параметры Bash (такие как `$0`, хранящий имя запущенной оболочки или скрипта) не подвергаются изменению регистра при вызове.
* **Команда:**
  ```bash
  # Внутри UPPERCASE shell вводим:
  $0
  # Произойдет вызов оригинального интерактивного shell (sh/bash) в обход фильтра.
  # Теперь мы в нормальном терминале:
  cat /etc/bandit_pass/bandit33
  ```
